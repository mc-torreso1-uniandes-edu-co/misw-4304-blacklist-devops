# Entrega 2 · Procedimiento para repetir la configuración de AWS del CI

Issue #104 · Épica E2 · Implementación

Este documento reúne en un solo lugar el orden y los comandos de la AWS CLI para volver a crear la
infraestructura del pipeline de integración continua: el bucket de artefactos, la conexión de GitHub, los roles,
el proyecto de CodeBuild y el pipeline. No repite el detalle de cada tarea: cada paso enlaza al documento que
registra su creación, sus decisiones y sus capturas. Parte del diseño de `docs/ci/1.1-diseno-pipeline.md` y no
reemplaza el enunciado oficial de `docs/entrega-2-integracion-continua.md`.

## 1. Recursos y orden de creación

Cada recurso depende de los anteriores, por eso el orden importa:

| Paso | Recurso | Nombre | Depende de | Documento de detalle |
|---|---|---|---|---|
| 1 | Bucket de S3 | `blacklist-devops-ci-artifacts-253041091381` | Nada | [1.4-bucket-artefactos.md](1.4-bucket-artefactos.md) |
| 2 | Conexión de GitHub | `blacklist-devops-github` | Nada (la autoriza el dueño del repositorio) | [1.6-conexion-github.md](1.6-conexion-github.md) |
| 3 | Rol de CodeBuild | `blacklist-devops-codebuild-role` | Bucket | [1.5-roles-iam.md](1.5-roles-iam.md) |
| 3 | Rol de CodePipeline | `blacklist-devops-codepipeline-role` | Bucket y ARN de la conexión | [1.5-roles-iam.md](1.5-roles-iam.md) |
| 4 | Proyecto de CodeBuild | `blacklist-devops-ci-build` | Rol de CodeBuild | [1.7-proyecto-codebuild.md](1.7-proyecto-codebuild.md) |
| 5 | Pipeline | `blacklist-devops-ci-pipeline` | Bucket, rol de CodePipeline, conexión y proyecto | [1.11-pipeline.md](1.11-pipeline.md) |

La conexión se crea antes que los roles porque la política del rol de CodePipeline usa el ARN de la conexión, que
lleva un identificador generado al crearla. Los ARN del proyecto y del pipeline se forman con su nombre, por eso
sus políticas se pueden escribir antes de que existan.

## 2. Antes de empezar

- **Cuenta y región.** Cuenta del proyecto (`253041091381`) y región `us-east-2` (Ohio) en todos los comandos.
- **Dónde se ejecutan.** El bucket, los roles y la conexión se crearon en la consola; para ellos, los comandos de los
  pasos 1 a 3 son el equivalente en la CLI. El proyecto y el pipeline se crearon con estos mismos comandos en AWS
  CloudShell, que usa las credenciales de la sesión de la consola. Con la CLI local se agrega `--profile blacklist` a
  cada comando.
- **Confirmación humana.** Crear recursos es una acción de escritura con costo potencial: cada comando de creación se
  ejecuta una sola vez, con confirmación previa, y no se repite sobre un recurso que ya existe. Los comandos de
  consulta de la sección 8 son de solo lectura.
- **Quién autoriza la conexión.** La conexión con GitHub solo la puede autorizar la persona dueña del repositorio.
- **Características avanzadas.** Si la consola muestra el aviso de **características avanzadas** del plan gratuito en
  cualquier paso, hay que detenerse: ninguna configuración activa esas características ni cambia de plan.

## 3. Paso 1 · Bucket de artefactos

Región `us-east-2`, acceso público bloqueado y cifrado SSE-S3. Detalle y capturas: `1.4-bucket-artefactos.md`.

```bash
aws s3api create-bucket \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381 \
  --create-bucket-configuration LocationConstraint=us-east-2

aws s3api put-public-access-block \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381 \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true

aws s3api put-bucket-encryption \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381 \
  --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"},"BucketKeyEnabled":false}]}'
```

## 4. Paso 2 · Conexión de GitHub

La CLI crea la conexión en estado *Pending*. La autorización en GitHub solo se puede hacer en el navegador, con la
cuenta dueña del repositorio: autorizar *AWS Connector for GitHub*, marcar **Only select repositories** y elegir solo
`misw-4304-blacklist-devops`, y volver a la consola para pulsar *Connect*. Detalle y capturas: `1.6-conexion-github.md`.

```bash
aws codeconnections create-connection \
  --provider-type GitHub \
  --connection-name blacklist-devops-github \
  --region us-east-2
```

El ARN que devuelve el comando se usa en la política del rol de CodePipeline (paso 3) y en la definición del
pipeline (paso 5). Si la conexión se crea de nuevo, ese ARN cambia y hay que actualizarlo en los dos lugares.

## 5. Paso 3 · Roles de servicio

Cada rol tiene una relación de confianza limitada a la cuenta y una sola política en línea, `acceso-minimo-ci`.
Los JSON están en `1.5-roles-iam.md`: las relaciones de confianza en la sección 3 y las políticas en la sección 4.
En `policy-codepipeline.json`, la sentencia `ConexionGitHub` lleva el ARN de la conexión del paso 2. Se guardan en
cuatro archivos antes de ejecutar los comandos:

| Archivo | Contenido |
|---|---|
| `trust-codebuild.json` | Relación de confianza del rol de CodeBuild (sección 3) |
| `policy-codebuild.json` | Política del rol de CodeBuild (sección 4.1) |
| `trust-codepipeline.json` | Relación de confianza del rol de CodePipeline (sección 3) |
| `policy-codepipeline.json` | Política del rol de CodePipeline (sección 4.2) |

```bash
aws iam create-role \
  --role-name blacklist-devops-codebuild-role \
  --description "Rol de servicio de CodeBuild para el build de integracion continua" \
  --assume-role-policy-document file://trust-codebuild.json

aws iam put-role-policy \
  --role-name blacklist-devops-codebuild-role \
  --policy-name acceso-minimo-ci \
  --policy-document file://policy-codebuild.json

aws iam create-role \
  --role-name blacklist-devops-codepipeline-role \
  --description "Rol de servicio de CodePipeline para el pipeline de integracion continua" \
  --assume-role-policy-document file://trust-codepipeline.json

aws iam put-role-policy \
  --role-name blacklist-devops-codepipeline-role \
  --policy-name acceso-minimo-ci \
  --policy-document file://policy-codepipeline.json
```

## 6. Paso 4 · Proyecto de CodeBuild

Origen y artefactos de CodePipeline, imagen de Amazon Linux, cómputo pequeño, sin variables de entorno y con el rol de
CodeBuild. Detalle y capturas: `1.7-proyecto-codebuild.md`.

```bash
aws codebuild create-project \
  --name blacklist-devops-ci-build \
  --source type=CODEPIPELINE \
  --artifacts type=CODEPIPELINE \
  --environment type=LINUX_CONTAINER,computeType=BUILD_GENERAL1_SMALL,image=aws/codebuild/amazonlinux-x86_64-standard:6.0 \
  --service-role arn:aws:iam::253041091381:role/blacklist-devops-codebuild-role \
  --logs-config cloudWatchLogs={status=ENABLED} \
  --region us-east-2
```

El proyecto usa el `buildspec.yml` de la raíz del repositorio.

## 7. Paso 5 · Pipeline

Pipeline V2 en modo `QUEUED`, con origen en GitHub, construcción en CodeBuild y los disparadores de *push* a `main` y
de *pull request* hacia `dev` y `main`. La definición completa está en `1.11-pipeline.md`, sección 4: se guarda en
`pipeline.json` antes de ejecutar el comando. Detalle y capturas: `1.11-pipeline.md`.

```bash
aws codepipeline create-pipeline --cli-input-json file://pipeline.json --region us-east-2
```

Al crearse, el pipeline inicia una ejecución por sí mismo. Si la rama `main` todavía no contiene el `buildspec.yml`,
esa primera ejecución falla en la descarga del origen; no indica un error de configuración.

## 8. Verificación

Todos los comandos son de lectura y se pueden repetir las veces que haga falta.

```bash
aws s3api head-bucket --region us-east-2 --bucket blacklist-devops-ci-artifacts-253041091381
aws s3api get-public-access-block --region us-east-2 --bucket blacklist-devops-ci-artifacts-253041091381
aws s3api get-bucket-encryption --region us-east-2 --bucket blacklist-devops-ci-artifacts-253041091381

aws iam get-role --role-name blacklist-devops-codebuild-role --query Role.Arn --output text
aws iam get-role-policy --role-name blacklist-devops-codebuild-role --policy-name acceso-minimo-ci
aws iam get-role --role-name blacklist-devops-codepipeline-role --query Role.Arn --output text
aws iam get-role-policy --role-name blacklist-devops-codepipeline-role --policy-name acceso-minimo-ci

aws codeconnections list-connections --region us-east-2
aws codebuild batch-get-projects --names blacklist-devops-ci-build --region us-east-2

aws codepipeline get-pipeline --name blacklist-devops-ci-pipeline --region us-east-2 \
  --query "pipeline.{tipo:pipelineType,modo:executionMode,triggers:triggers}"
aws codepipeline list-pipeline-executions --pipeline-name blacklist-devops-ci-pipeline --region us-east-2
```

### 10.1 Revisión de las capturas

El 26 de octubre de 2026 se revisó una por una cada captura de los documentos 1.4, 1.5, 1.6, 1.7 y 1.11:

- **Secretos.** Ninguna muestra tokens, contraseñas, llaves de acceso, `DATABASE_URL`, `JWT_SECRET_KEY` ni variables de
  entorno con valores. Aparecen el número de cuenta y los ARN, que no son secretos, y las políticas de IAM, que
  contienen solo nombres y ARN de recursos.
- **Legibilidad.** Las capturas de pantalla completa miden unos 1900 píxeles de ancho. Se leen bien a tamaño real o en
  el video; en una página del PDF, a ancho de página, el texto pequeño de algunas se vuelve difícil de leer, y
  conviene recortarlas a la zona que importa.
