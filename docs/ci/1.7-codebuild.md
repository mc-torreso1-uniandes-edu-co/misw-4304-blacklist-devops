# Configuración del bucket S3 para los artefactos de CI

## Issue y alcance

Issue #96 · Entrega 2 · Épica 1 · Implementación

Este registro documenta exclusivamente la creación y verificación del bucket de Amazon S3 que
almacenará los artefactos generados por el pipeline de integración continua. No documenta todavía la
creación del proyecto de CodeBuild ni la configuración completa de CodePipeline; esas actividades se
realizan en los issues correspondientes.

La configuración se realizó el **22 de octubre de 2026** en la cuenta del proyecto y en la región
`us-east-2` (Ohio). La creación se hizo desde la consola de AWS para conservar evidencia visual y las
verificaciones se repitieron con AWS CLI en modo de solo lectura.

## 2. Configuración aplicada

### 2.1 Propiedad de los objetos

Se dejó `ACLs disabled` con `Bucket owner enforced`. De esta forma, los objetos pertenecen a la cuenta
del proyecto y el acceso se controla mediante políticas, no mediante listas de control de acceso (ACL).

### 2.2 Bloqueo del acceso público

Se activó **Block all public access**. Las cuatro opciones quedaron habilitadas:

| Configuración | Estado |
|---|---|
| `BlockPublicAcls` | `true` |
| `IgnorePublicAcls` | `true` |
| `BlockPublicPolicy` | `true` |
| `RestrictPublicBuckets` | `true` |

No se creó una política pública para el bucket.

### 2.3 Cifrado predeterminado

Se configuró cifrado del lado del servidor con claves administradas por Amazon S3:

```text
SSE-S3 / AES256
```

No se configuró SSE-KMS ni DSSE-KMS, porque el alcance de #96 no requiere una clave administrada por
KMS.

**Bucket Key desactivado.** Al crear el bucket, el formulario lo dejó habilitado por defecto con SSE-S3
(ver [1.4-formulario-versionado-cifrado.png](../capturas/entrega-2/1.4-formulario-versionado-cifrado.png)).
Después de crear el bucket se desactivó desde *Properties → Default encryption → Edit*, como parte de la
configuración final acordada. Se verificó por CLI (`BucketKeyEnabled: false`).
La consola indica que Bucket Key solo reduce las llamadas a KMS; con SSE-S3 no tiene efecto sobre los
objetos. El algoritmo efectivo es `AES256`.

Capturas del cambio: [1.4-bucket-key-edicion.png](../capturas/entrega-2/1.4-bucket-key-edicion.png) y
[1.4-bucket-key-guardado.png](../capturas/entrega-2/1.4-bucket-key-guardado.png). Estado final en la
consola: [1.4-cifrado-estado-final.png](../capturas/entrega-2/1.4-cifrado-estado-final.png), con SSE-S3,
Bucket Key en *Disabled* y SSE-C bloqueado.

También quedó bloqueado el cifrado SSE-C.

## 3. Comando equivalente de creación

La creación se realizó desde la consola. El comando equivalente para reproducirla con AWS CLI es:

```bash
aws s3api create-bucket \
  --profile blacklist \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381 \
  --create-bucket-configuration LocationConstraint=us-east-2
```

El comando solo debe ejecutarse si el bucket no existe. La creación de recursos AWS requiere
confirmación humana previa y no debe repetirse sobre el bucket existente.

## 4. Comandos de configuración equivalente

Estas son las operaciones equivalentes para reproducir la configuración aplicada. Se documentan como
referencia; no se ejecutaron nuevamente después de la creación porque la configuración ya se aplicó
desde la consola.

### Bloqueo de acceso público

```bash
aws s3api put-public-access-block \
  --profile blacklist \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381 \
  --public-access-block-configuration \
  BlockPublicAcls=true,IgnorePublicAcls=true,BlockPublicPolicy=true,RestrictPublicBuckets=true
```

### Cifrado predeterminado SSE-S3

```bash
aws s3api put-bucket-encryption \
  --profile blacklist \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381 \
  --server-side-encryption-configuration \
  '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"},"BucketKeyEnabled":false}]}'
```

## 5. Verificación con AWS CLI

Las consultas se ejecutaron después de crear el bucket. No se ejecutó ninguna operación de escritura
durante esta verificación.

### Identidad de la cuenta

Comando:

```bash
aws sts get-caller-identity \
  --profile blacklist \
  --region us-east-2
```

Resultado relevante:

```json
{
  "Account": "253041091381",
  "Arn": "arn:aws:sts::253041091381:assumed-role/AccountFullAccessRole/..."
}
```

### Existencia y región

Comando:

```bash
aws s3api head-bucket \
  --profile blacklist \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381
```

Resultado: la consulta terminó correctamente y devolvió:

```json
{
  "BucketArn": "arn:aws:s3:::blacklist-devops-ci-artifacts-253041091381",
  "BucketRegion": "us-east-2",
  "AccessPointAlias": false
}
```

Comando adicional:

```bash
aws s3api get-bucket-location \
  --profile blacklist \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381
```

Resultado:

```json
{
  "LocationConstraint": "us-east-2"
}
```

### Bloqueo de acceso público

Comando:

```bash
aws s3api get-public-access-block \
  --profile blacklist \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381
```

Resultado:

```json
{
  "PublicAccessBlockConfiguration": {
    "BlockPublicAcls": true,
    "IgnorePublicAcls": true,
    "BlockPublicPolicy": true,
    "RestrictPublicBuckets": true
  }
}
```

### Cifrado predeterminado

Comando:

```bash
aws s3api get-bucket-encryption \
  --profile blacklist \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381
```

Resultado relevante:

```json
{
  "ServerSideEncryptionConfiguration": {
    "Rules": [
      {
        "ApplyServerSideEncryptionByDefault": {
          "SSEAlgorithm": "AES256"
        },
        "BucketKeyEnabled": false,
        "BlockedEncryptionTypes": {
          "EncryptionType": ["SSE-C"]
        }
      }
    ]
  }
}
```

Esta consulta se hizo después de desactivar Bucket Key (sección 2.3): `BucketKeyEnabled` es `false` y el
cifrado sigue siendo SSE-S3 (`AES256`). Se conserva el bloqueo de SSE-C.

### Bucket vacío

Comando:

```bash
aws s3api list-objects-v2 \
  --profile blacklist \
  --region us-east-2 \
  --bucket blacklist-devops-ci-artifacts-253041091381
```

Resultado: la respuesta no contiene `Contents`; únicamente informa el prefijo vacío y
`RequestCharged: null`. Por tanto, no hay objetos almacenados en el bucket.
