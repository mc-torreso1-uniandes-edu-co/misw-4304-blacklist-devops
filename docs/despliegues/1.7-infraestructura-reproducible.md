## 1. Objetivo y alcance

Crear la infraestructura en AWS de forma que pueda encenderse y apagarse en cada ventana de trabajo sin rehacer la configuración, para controlar el costo. La primera creación fue manual por consola. Toda acción con costo se confirma con el equipo.

## 6. Configuración reproducible

- Configuración guardada como `blacklist-base` (*Actions → Save configuration*). Se vuelve a guardar cada vez que cambie la configuración del entorno.
- Prefijo de URL fijo, para recrear el entorno con la misma dirección.

## 7. Procedimiento de encendido y apagado

### 7.1 Encender una ventana de trabajo

1. Iniciar RDS (`blacklist-db`) y esperar el estado *Available*.
2. Recrear el entorno desde `blacklist-base` con el mismo nombre y el mismo prefijo de URL, o usar *Restore environment* si el entorno terminado aún está disponible (hasta 6 semanas).
3. Verificar salud *Ok* con 3 instancias y `/ping` respondiendo la versión.
4. Registrar la ventana en la tabla de la sección 8.

### 7.2 Apagar al cerrar la ventana

1. Guardar la configuración como `blacklist-base` si cambió.
2. Terminar el entorno `blacklist-devops-env`.
3. Detener RDS (`blacklist-db`). AWS la reinicia sola a los 7 días, así que hay que volver a detenerla si la ventana se alarga.
4. Verificar en la consola que el entorno y la base están detenidos o terminados.
5. Cerrar la ventana en la tabla de la sección 8.

> Nota: el ciclo completo (apagar, encender y recrear) aún no se ha probado de principio a fin. Ver la sección 10.

- **Rotación de `JWT_SECRET_KEY`**: si el valor actual se compartió fuera del gestor de contraseñas, rotarla y regenerar el token.
- **Nombre del entorno y zonas**: confirmar que coinciden con el issue.
