## 1. Objetivo y alcance

Crear la infraestructura en AWS de forma que pueda encenderse y apagarse en cada ventana de trabajo
sin rehacer la configuración, para controlar el costo. La primera creación fue manual por consola.
Toda acción con costo se confirma con el equipo.

Propiedades de entorno (solo nombres, sin valores): `APP_ENV`, `DATABASE_URL`, `JWT_SECRET_KEY`,
`PYTHONPATH` y, desde el 15 de octubre de 2026, `PROXY_FIX_X_FOR` con valor `2` (no es secreta).

**`PROXY_FIX_X_FOR = 2`.** En Beanstalk la solicitud pasa por el balanceador y por el nginx de la
instancia, y cada uno agrega una entrada a `X-Forwarded-For` (`cliente, IP del balanceador`). Con un
solo salto se guardaba la IP privada del balanceador (`172.31.21.107`) en lugar de la del cliente. Con
dos saltos se guarda la del cliente, y una entrada falsa enviada por el cliente queda a la izquierda y
no se toma. La propiedad está en el entorno y en `blacklist-base`; requiere una versión que la lea
(`v1.1` o posterior, #57).

Se confirmó que la política de despliegue *Rolling* se puede elegir sin el aviso de "características
avanzadas" del plan gratuito.

### 5.1 Particularidades que quedaron documentadas

- **Nombre del entorno**: en AWS es `Blacklist-devops-env` (con mayúscula inicial). El issue lo
  escribió como `blacklist-devops-env`. Se documenta el nombre real y no se renombró el entorno.
- **`PYTHONPATH`**: la plataforma de Python de AL2023 ejecuta la aplicación dentro de un entorno
  virtual propio, así que esta variable no la definió el equipo. El valor observado apunta a un
  directorio de *staging* (`/var/app/venv/staging-.../bin`). Se deja registrada para **revisar si es
  necesaria o si conviene eliminarla** antes del siguiente despliegue.
- **Actualizaciones administradas**: la plantilla se creó con `ManagedActionsEnabled = true`; el
  12 de octubre de 2026 se cambió a `false` en `blacklist-base` (sin recrear el entorno), con el
  resto de opciones intacto.

## 6. Configuración reproducible

- Configuración guardada como `blacklist-base` (*Actions → Save configuration*). Se vuelve a guardar
  cada vez que cambie la configuración del entorno.
- La plantilla `blacklist-base` conserva: Auto Scaling 3–6, perfil `blacklist-ec2-instance-rol`,
  grupo `blacklist-app-sg`, rol de servicio `blacklist-eb-service-rol`, health check `/ping`,
  logs a CloudWatch desactivados y actualizaciones administradas desactivadas.
- Prefijo de URL fijo, para recrear el entorno con la misma dirección.

## 7. Procedimiento de encendido y apagado

En la Entrega 1 hay un solo encendido: empieza con el primer despliegue (15 de octubre de 2026) y se
mantiene durante las pruebas contra AWS y las estrategias de despliegue, hasta grabar el video. El
apagado se hace una vez, después de la grabación.

### 7.1 Encender una ventana de trabajo

1. Iniciar RDS (`blacklist-db`) y esperar el estado *Available*.
2. Recrear el entorno desde `blacklist-base` con el mismo nombre y el mismo prefijo de URL, o usar
   *Restore environment* si el entorno terminado aún está disponible (hasta 6 semanas).
3. Verificar salud *Ok* con 3 instancias y `/ping` respondiendo la versión.
4. Registrar la ventana en la tabla de la sección 8.

**Rol de servicio al recrear desde la consola.** Al cargar `blacklist-base`, el formulario de creación
de la consola propone el rol de servicio `aws-elasticbeanstalk-service-role` en lugar de
`blacklist-eb-service-rol`. Como la plantilla usa `blacklist-eb-service-rol` como rol de las actualizaciones administradas, la
creación falla con `Invalid option specification (Namespace: 'aws:elasticbeanstalk:managedactions',
OptionName: 'ServiceRoleForManagedUpdates')`. Ocurrió dos veces el 15 de octubre de 2026. Para evitarlo:

- En la consola, elegir **`blacklist-eb-service-rol`** como rol de servicio antes de crear el entorno.
- O crear el entorno por CLI, que toma los roles de la plantilla sin cambios (así se creó el 15 de
  octubre de 2026):

  ```
  aws elasticbeanstalk create-environment --region us-east-2 \
    --application-name blacklist-devops --environment-name Blacklist-devops-env \
    --cname-prefix blacklist-devops-misw --template-name blacklist-base --version-label v1
  ```

Cada intento fallido desde la consola deja una versión de aplicación con nombre automático
(`app-AAMMDD_HHMMSS`) que apunta al mismo zip. Se puede borrar desde *Versiones de la aplicación*,
**sin** marcar la opción de borrar el paquete de S3, porque el zip es el de la versión real.

### 7.2 Apagar al terminar el trabajo

1. Guardar la configuración como `blacklist-base` solo si cambió la configuración base. No se guarda
   la política de despliegue de una estrategia: la plantilla se deja con `AllAtOnce`.
2. Terminar el entorno `Blacklist-devops-env`.
3. Detener RDS (`blacklist-db`). AWS la reinicia sola a los 7 días, así que hay que volver a
   detenerla si la ventana se alarga.
4. Verificar en la consola que el entorno y la base están detenidos o terminados.
5. Cerrar la ventana en la tabla de la sección 8.

### 7.3 Costo de referencia (us-east-2, consultado el 12 de octubre de 2026)

Precios bajo demanda de la lista de precios de AWS:

| Recurso | Precio | Cálculo |
|---|---|---|
| EC2 `t3.micro` Linux | 0,0104 USD/hora | × 3 instancias = 0,0312 USD/hora |
| Application Load Balancer | 0,0225 USD/hora (+ 0,008 USD por LCU-hora) | 0,0225 USD/hora |
| RDS `db.t4g.micro` PostgreSQL, una zona | 0,0160 USD/hora | 0,0160 USD/hora |
| **Total por hora encendida** | | **≈ 0,0697 USD/hora (≈ 0,07 USD)** |
| Almacenamiento RDS gp3, una zona | 0,115 USD/GB-mes | × 20 GB = 2,30 USD/mes |
| Almacenamiento EBS gp3 (volúmenes de instancia) | 0,08 USD/GB-mes | se borra al terminar el entorno |

Notas:
- La capa gratuita (12 meses) suele cubrir 750 horas/mes de `t3.micro` y 750 horas/mes de
  `db.t4g.micro`; **el Application Load Balancer no está cubierto**, por eso el entorno es el que más
  pesa por hora.
- Con el entorno terminado, casi todo el costo por hora desaparece; solo queda el almacenamiento de
  RDS. La estimación es informativa y el cobro real depende del plan de la cuenta y de la facturación.

### 7.4 Después de la entrega: eliminar y volver a proveer

Según la aclaración del tutor (`docs/aclaraciones-entrega-1.md`), los recursos solo deben estar
disponibles durante el trabajo y la grabación del video, pero el ambiente debe poder volver a
proveerse si el tutor cita a una sustentación síncrona.

**Eliminar (después de la fecha de entrega):**

1. Terminar el entorno `Blacklist-devops-env` si quedó encendido.
2. Eliminar la RDS `blacklist-db` con **snapshot final** (*Create final snapshot*), con el nombre
   `blacklist-db-final-entrega-1`. No se deja detenida: AWS la vuelve a encender a los 7 días y cobra
   por hora.
3. Conservar la configuración guardada `blacklist-base`, las versiones de la aplicación en S3, los
   grupos `blacklist-app-sg` y `blacklist-db-sg` y los roles del proyecto.
4. Verificar en la consola que no quedan instancias, balanceadores ni bases en ejecución.

**Volver a proveer (sustentación síncrona, unos 20 minutos):**

1. Restaurar el snapshot `blacklist-db-final-entrega-1` con el identificador `blacklist-db`, la misma
   clase (`db.t4g.micro`), sin acceso público y con el grupo `blacklist-db-sg`. Con el mismo
   identificador, la dirección de conexión es la misma y `DATABASE_URL` no cambia.
2. Esperar el estado *Available*.
3. Recrear el entorno desde `blacklist-base`, con el mismo nombre y el mismo prefijo de URL, y elegir
   la última versión de la aplicación ya cargada (ver el rol de servicio en la sección 7.1).
4. Verificar salud *Ok* con 3 instancias, `/ping` con la versión esperada y la colección de Postman
   contra la URL del entorno.
5. Al terminar la sustentación, repetir los pasos de eliminación.

## 11. Decisiones pendientes

- **Respuesta de `/ping`**: el equipo debe decidir si responde solo `{"version": ...}` o también
  `status`. El enunciado no fija el cuerpo.
- **Rotación de `JWT_SECRET_KEY`**: si el valor actual se compartió fuera del gestor de contraseñas,
  rotarla y regenerar el token.
- **`PYTHONPATH`**: revisar si es necesaria o eliminarla de las propiedades del entorno.
- **Capturas con variables de entorno**: no versionar imágenes que muestren los valores de
  `DATABASE_URL` o `JWT_SECRET_KEY`.
