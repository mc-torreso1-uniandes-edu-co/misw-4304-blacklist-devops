# Entrega 2 · Matriz de escenarios de prueba por endpoint

Tarea 2.1 (#105) · Épica E2 · Pruebas

Este documento relaciona la suite de pruebas actual con cada endpoint de la API y marca los escenarios que
faltan. Sirve de base para completarlos en las tareas 2.2 (#106) y 2.3 (#107), y para dejar la suite lista
para el pipeline en la tarea 2.4 (#108).

Cubre el punto 1 de la configuración del enunciado (`docs/entrega-2-integracion-continua.md`): al menos
un escenario de prueba unitaria por endpoint, que pasa y que corre en el pipeline (30 %).

## 6. Observación sobre la forma de las pruebas de 401

`test_post_rejects_invalid_credentials_with_unauthorized` y
`test_get_rejects_invalid_credentials_with_unauthorized` recorren las cinco variantes de credencial
dentro de un solo `for`. Si una variante falla, el reporte del build solo muestra el nombre de la prueba y
la etiqueta aparece en el mensaje de la aserción. Con `pytest.mark.parametrize` quedaría un caso por
variante y el resultado del pipeline indicaría cuál falló. Se propone hacerlo en 2.2 (#106) para `POST` y
en 2.3 (#107) para `GET`.
